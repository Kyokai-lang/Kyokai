# Parser Conformance Lane

This lane contains accepted and rejected single-file `.kyo` grammar fixtures, the one source-file start symbol, per-declaration visibility and opacity, declaration terminators, semantic block terminators, imports, module headers, and source-span expectations.

Current status: the represented Phase 3 surface is implemented behind the composed `KyokaiFrontend` path. Supporting host tests live in `test/host/frontend/KyokaiSurfaceParserTest.ml`, `test/host/frontend/KyokaiFrontendTest.ml`, and `test/host/frontend/KyokaiControlFlowValidationTest.ml`. The `implementation-gated` fixture packs exercise source skeletons, spans, inherited-form rejection, declarations, borrow and function-pointer types, generic classifiers and obligations, method and generator bodies, inline tests with explicit capability parameters, foreign and unsafe-audit surfaces, expressions, structural patterns, and executable statements. The structural validator rejects misplaced loop exits, `yield`, `produce`, and `spawn`; test declarations remain private to their source module and outside the derived interface. Name and type resolution, D238 elaboration, ownership and cleanup, test discovery/lowering, label resolution, divergence, refutability, evaluation, and public conformance remain open. The internal compiler-stage runner executes these fixtures as supporting evidence only.
